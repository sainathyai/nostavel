# UI review

## Setup

1. Read the design brief (`docs/design/NOS-<n>.md`) and the pull request. List every
   state and screen you must reach, and how to trigger each one.
2. Build and start the app on a free port, and check the port is actually yours before
   trusting what you see: a stale server from an earlier run can serve an old build.
3. Stop the server when you finish.

## What to check

For each screen or component in the brief:

1. **States.** Reach every one: empty, loading, error, success, partial. Say how you
   triggered it. If a state can't be reached, say why.
2. **Widths.** 375 px and 1280 px. Look for horizontal scrolling, clipped text, overlap,
   a sticky panel taller than the viewport, and a long label squeezing a price
   (conventions §9).
3. **Themes.** Light and dark. Check contrast of text, borders and disabled states, and
   that nothing disappears into its background.
4. **Keyboard.** Tab through: every interactive element reachable, focus visible, order
   sensible, dialogs trap and release focus, Escape closes.
5. **Accessibility.** Labels on inputs, `alt` on meaningful images, buttons that are
   buttons, status changes announced, nothing conveyed by colour alone. Run an automated
   accessibility check if the tool has one, and treat its output as a starting point.
6. **Console.** Report errors and warnings from the pages you visited.
7. **Content.** Prices, deadlines and inclusions match the brief, estimates are labelled,
   and nothing shows a placeholder or a raw error string.

## Report

```
UI review: NOS-<n>
Build: <commit> on <url>

States checked: <state -> screenshot, how triggered>
Not reached: <state -> why>
Findings (most severe first)
1. [high|medium|low] <screen, element> - <what is wrong> - <screenshot>
Console: <errors and warnings>

Owner, please look at:
- <url> - <what to judge: spacing, tone, whether it reads honestly>
```

## Boundaries
Report, don't fix. Findings go to frontend-engineer. Visual taste is the owner's call
(conventions §7): give them the URL and say what to judge.

Known environment limit: the map basemap is unavailable until the deploy segment, so map
areas show their fallback message. Note it; don't report it as a new fault.
